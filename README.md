# 中文写作与润色

一个用于中文起草、润色、去AI腔和风格校准的Agent Skill。适合邮件、报告、文章与学术段落。

它着重解决三个问题：把意思写清楚，保留作者语气，避免润色时改动事实。没有机械禁词表，也不会靠编数字、造经历或添加口头禅让文字显得具体。

## 使用

将[skills/chinese-writing](skills/chinese-writing)作为完整技能目录交给支持`SKILL.md`的工具；保留其中的`references`和`agents`子目录。具体安装位置以所用工具的说明为准。

如果只想手动使用提示词，打开[SKILL.md](skills/chinese-writing/SKILL.md)，复制顶部YAML之后的正文。补充示例位于[references/examples.md](skills/chinese-writing/references/examples.md)。

可直接这样提问：

```text
请用$chinese-writing润色下面的中文，保留数字和限定条件，直接给成稿：
[粘贴原稿]
```

```text
根据下面的要点写一封给同事的邮件，语气自然、礼貌，不要添加我没有承诺的事项：
[粘贴要点]
```

```text
把这段报告改得自然一些。不要把相关关系改成因果关系，专业术语保持一致：
[粘贴原稿]
```

```text
这是我以前写的两段文字，请参照语气改写后面的新稿。不要把样本里的事实写进新稿：
[风格样本]
[新稿]
```

## 工作方式与边界

- 起草时依托已有材料，关键事实缺失就明确留空或询问。
- 润色时默认小幅修改；大幅重写需要来自用户的要求。
- “赋能”、排比、破折号和三点列表都不是自动删除对象，要看实际作用。
- 学术文本保留显著性、单位、否定、相关与因果的区别。
- 默认输出可直接使用的文字，需要时才解释改动。
- 纯润色不代表核实了事实，也不承诺通过任何AI文本检测器。

本仓库以可移植Markdown为主，不依赖API密钥、外部模型或运行脚本。`agents/openai.yaml`提供可选的Codex界面信息。不同工具的自动触发效果仍取决于各自的技能加载方式。
